Design Patterns Used

Observer Pattern

Implemented through Unity Events (UnityAction) for decoupled communication.

  • onCorrectPlacement (pyramidSlot)
  • onTabletPlaced (slotHandler)
  • onMassChanged (MassHandler)
  • onItemDropped (plate_logic)

Manager Pattern

Centralized control for each puzzle's state and completion logic.

  • room1_Manager (Pyramid Puzzle)
  • Room3_Manager (Cipher Puzzle)
  • jigsaw_manager (Balance Puzzle)

Component Pattern

Unity's GameObject-Component architecture for modular, reusable code.

  • plateVisual (rendering)
  • plate_logic (state)
  • MassHandler (physics)
  • Audio components created dynamically

State Pattern

Boolean flags track component states to prevent invalid operations.

  • isFilled (pyramidSlot)
  • isPlaced (slotHandler)
  • isLocked (tabletHandler)
  • keyParts counter (keyplacment)
  • start flag (doorcontroller)

Strategy Pattern

Different validation strategies for each puzzle type.

  • ID Matching (Pyramid & Cipher)
  • Mass Balancing (Balance Puzzle)
  • Tag Matching (Key Assembly)
  • Collision Detection (Triggers)

Coroutine Pattern

Unity coroutines for smooth animations and timed sequences.

  • OpenDoor/CloseDoor (doorcontroller)
  • OpenDoor (keyplacment)
  • arise (keyplaceariser)
  • AnimateSnap (tabletHandler)

Key Architectural Decisions

  • ▸ Event-Driven Architecture: Heavy use of UnityEvents enables loose coupling between puzzle components and managers, making the system highly modular and extensible.
  • ▸ Physics-Based Interactions: Leverages Unity's physics system (Rigidbody, Colliders) for natural VR object manipulation and collision detection.
  • ▸ Coroutine-Based Animation: Smooth, non-blocking animations for doors, keys, and objects using Unity coroutines with interpolated movement.
  • ▸ Tag-Based Identification: Uses Unity's tag system for quick object identification (Player, pyramidToken, Tablet, weight_object, left/right/head).
  • ▸ Dynamic Audio System: Runtime AudioSource creation with spatial audio (spatialBlend = 1) for immersive 3D sound effects.
  • ▸ No Database Required: Offline-first design using local storage (PlayerPrefs, JSON, Scriptable Objects) optimized for Meta Quest 2.
  • ▸ Modular Puzzle Design: Each puzzle is self-contained with its own manager and handlers, enabling independent development and testing.
  • ▸ Progressive Challenge: Key assembly system creates a satisfying climax by unifying all three puzzle solutions into a dramatic escape sequence.
